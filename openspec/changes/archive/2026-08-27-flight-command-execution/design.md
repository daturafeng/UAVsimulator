## Context

模块骨架已就绪：UAVDroneSim 有简单插值移动与飞行状态枚举，UAVFlightControl 有指令枚举占位，UAVCameraStream 只有 RTMP 地址字段（见 proposal.md - Why）。d 协议来源为 dock 项目（D:\WebCode\dock）的上云 API 模拟脚本与 cloud-sdk，首期设备标识：机场 DOCK3TEST001（dock3）、无人机 1581F8HGXTEST001（M4TD，相机索引 52-0-0，视频类型 zoom/wide/ir）。

## Goals / Non-Goals

**Goals:**

- 让"指令 → 状态机 → 运动模拟"主链路按上云 API 协议跑通，且可脱离 MQTT 单独测试（直接调用 API 注入指令）。
- 地理坐标转换与航点移动可在编辑器/自动化测试中验证。

**Non-Goals:**

- 不接入 MQTT 客户端（下一变更使用 UE 自带 MQTTCore 插件）。
- 不做真实 RTMP 编码推流（本变更仅定义直播会话模型与接口）。
- 不做云台/载荷控制（DRC）与拍照录像。

## Decisions

- **局部 ENU 坐标系，机场为原点**：无人机与机场距离通常在数公里内，使用机场为原点的北-东-上局部坐标系即可满足精度；场景轴约定：X=东、Y=北、Z=上，避免与 UE 默认轴混淆，通过配置常量统一。备选（直接使用 UE 全局坐标+偏移）不可逆且难维护，不采用。
- **纬度/经度换算用等距近似公式**（纬度 1° ≈ 110540m、经度 1° ≈ 111320×cos(lat) m）：与 dock 项目 common.py 一致，保证联调口径统一；误差在近场模拟可接受。备选（WGS84 椭球精确公式）需引入地理库，超出首期范围。
- **指令解析以 method 分发、参数独立结构体**：每个指令一个参数结构体（FTakeoffToPointParams 等），解析器把 JSON 字段映射到结构体，状态机消费结构体。备选（直接操作 JSON 树）导致状态机与协议耦合，不采用。
- **运动模拟采用"航点 + 速度矢量"模型**：当前航点与当前位置的差向量按最大水平速度钳制，垂直速度独立按高度差驱动，到达阈值 1.5m。备选（物理动力学）过度复杂，首期不需要。
- **飞控状态机独立于指令解析**：解析层只产出"意图"（结构体），状态机负责合法性校验（是否已抢权、当前是否可中断）与状态迁移，便于测试。
- **事件由状态机产出、桥接层转发**：本变更暴露委托/回调接口（OnTakeoffProgress、OnWaylineProgress），MQTT 层订阅并拼装 services_reply/events 报文。

## Risks / Trade-offs

- [经纬度近似换算在远距离（>10km）误差累积] → 首期任务范围限制在机场周边数公里；文档注明适用边界。
- [UE 轴约定与经纬度映射混淆] → 所有换算集中在 UAVGeoUtils 单点实现，暴露 Blueprint 可调用函数并加单元断言。
- [飞行状态枚举与上云 API mode_code 语义不一致] → 状态机维护自己的状态，OSD 层再做 mode_code 映射（后续变更）。
